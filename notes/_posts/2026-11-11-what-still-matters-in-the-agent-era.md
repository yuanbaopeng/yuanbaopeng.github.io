## 问题

Agent 写代码已经很快，市面上的产品和编排工具也越来越多。我想弄清两件事：如果“写代码”本身不再是主要工作，当前做什么还值钱；面对 Hermes、DeepSeek Harness、Orca、T3 这类名字，该怎么选，而不是追着每款新工具跑。

## 要点

- 变的是亲手敲每一行代码这件事，不是工程本身。做什么、做得对不对、出了问题怎么查，仍然要人来判断。
- 眼下更值钱的，是把模糊需求拆成可执行任务、把住系统设计、做验证和评测，以及自己领域里的知识。会给 Agent 准备上下文、拆任务、同时管好几个 Agent，本身也是一门新手艺。
- 工具可以先分成两层：一层是自己干活的 Agent 或 harness，一层是把已有 Agent 放到同一个界面里调度的控制台。
- 我已经在用 Cursor。先把它用熟就够了：把任务说清楚、让 Agent 改代码、自己负责设计和验收。Orca、T3 这类编排工具，等真的经常同时开好几个 Agent、互相打架了，再考虑。

## 展开

### 人还要做什么

我不太接受“写代码已经没有意义了”这个说法。Agent 能很快交出代码，但也很容易把系统越写越乱，或者悄悄埋下 bug。所以工作更像从“写代码的人”变成“对结果负责的人”。

具体一点，有这几件事现在更突出：定义问题和需求；系统设计和品味，包括取舍和删掉不该留下的代码；写测试、做评测、看懂 Agent 写的代码；把行业知识和用 Agent 的能力叠在一起。更底层的训练、推理和 kernel，也仍然需要懂系统的人。

### 工具怎么分类

直接能用的，是 ChatGPT、Claude、Gemini、Cursor、Claude Code、Codex 这类产品和助手。要把多个 Agent 串成固定流程，才轮到编排工具或框架。

后来对上的几个名字，路线并不一样：

- Hermes 是开源、可自己部署的个人助手，强调记忆和把做过的事沉淀成技能，模型可以换，不绑死在一家上。
- Grok 是现成的闭源产品，出现在 X、grok.com 和一些开发工具里，不用自己搭整套系统，也不能像 Hermes 那样随意换底座、自己托管。
- DeepSeek Harness（也叫 dsh）是一层运行时：工具、沙箱、任务循环、权限和插件。模型是大脑，harness 是手脚和规矩。它更偏开发者框架，核心说法是“一切皆插件”，定位接近开源的编码 Agent。
- Orca 和 T3 Code 都不是新的模型，也不是自己干活的 harness，而是控制台：用你已有的订阅，在一个界面里调度多个编码 Agent。Orca 更强调并行和隔离，任务通常进独立的 worktree，也可以丢到远程机器上继续跑。T3 更强调一条对话可以中途换 Agent、看完 diff 开 PR、让一个 Agent 把子任务交给另一个。

可以这么记：DeepSeek Harness、Hermes、Claude Code 是“厨房”，Orca 和 T3 是“餐厅”。目标都需要时，也不必两套一起装；并行和隔离是更基础的能力，工作流上的不顺手以后再补。

### 怎么选

工具会一直换。判断“做什么、做得对不对”才是一直值钱的部分。对现在的我来说，先把 Cursor 用熟，比同时跟上每一款新的 harness 或编排层更重要。

## 还没确认的

- 上面这些产品的具体能力、许可证、是否还在开发者预览，以及“字节扣子企业版逐步下线、腾讯元器停服”这类市场消息，都只来自当时的公开介绍，没有逐一复查官网或自己装过。
- DeepSeek Harness 与 DeepSeek-V4-Pro 是否同一时期推出、本地一条 `npx` 命令能否原样启动，没有实际跑过。
- Orca 和 T3 的功能边界是按当时公开资料归纳的，两款产品都还在迭代，侧重点以后可能接近。
